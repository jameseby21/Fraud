# CP-004: publication guard

Scope: local commit/push gates for the public repository, without opening private vaults.

Test-first evidence: the first test run failed because the publication-guard module was absent. Six initial tests then passed. Additional tests exposed missed indented private-key headers and renamed encrypted/plaintext vault documents; these cases were fixed and retained as regressions.

The guard inspects actual Git index blobs, not unstaged working copies. It rejects protected paths even after force-add, recognized vault envelopes/documents, common private-key headers, selected GitHub credential patterns, and cloud access-key identifiers. Findings report paths and rule names without matched secret values. Large unreviewed blobs fail the automatic gate.

Tracked pre-commit/pre-push hooks invoke the guard. The pre-commit hook also checks staged data byte integrity. Hooks are enabled locally with `git config core.hooksPath .githooks`; other clones must enable them separately. Hooks can be bypassed and heuristics are incomplete, so manual review remains mandatory.

Validation: 71 tests pass with the optional vault environment. Tests cover force-added ignored files, unstaged-versus-staged content, redacted diagnostics, indented keys, and renamed documents. The full tracked-index scan passes. No private user record is used in tests or committed.
