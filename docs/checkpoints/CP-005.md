# CP-005: encrypted note workflow

Scope: interactive local notes using the external encrypted vault. No HTTP unlock, browser persistence, or automatic publication.

Test-first evidence: the initial note suite failed because the module did not exist. Ten initial persistence, revision, validation, and CLI tests then passed. Additional tests checked default-versus-explicit history display, malformed revision sequences, and C1 terminal control characters. The latter exposed an accepted control sequence; validation was extended and the regression retained.

Implemented hidden prompts for case/type/title/body, encrypted note creation, metadata listing, explicit local reads, corrections with reasons, preserved earlier versions, and stale-note revision rejection. Observation, hypothesis, counterevidence, and review notes are distinct. No note automatically becomes a proven-fraud label. All record operations retain the vault's wrong-key, revision, lock, and OS storage protections.

Validation: 83 tests pass with optional dependencies, including 12 note-workflow tests. A reopened vault recovers notes; only ciphertext remains on disk; default read omits prior bodies, while explicit `--history` displays them. Listing omits bodies and correction reasons. Errors do not echo paths, passphrases, or note content.

Limits: local list/read commands intentionally reveal selected plaintext in the terminal. The CLI body prompt currently accepts one line. History is preserved by this workflow, not cryptographically notarized against someone who holds the key and rewrites the document. The browser remains isolated.
