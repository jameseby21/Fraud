# CP-001: public-award quality audit

Date: October 21, 2026. Scope: one read-only audit of the existing public award sample, with an inspectable UI and downloadable report. No new real-person allegations or fraud predictions.

## Acceptance written before implementation

- Clean rows pass limited checks without implying absence of fraud.
- Empty inputs remain explicitly empty.
- Missing fields, duplicate identifiers, malformed integer cents, invalid dates, reversed ranges, unsupported currencies, synthetic contamination, and unexpected labels are reported.
- Negative obligations are informational because legitimate adjustments can produce them.
- Findings identify CSV rows and award keys; reports are deterministic and leave inputs unchanged.
- The API includes input/source hashes and returns an identical downloadable report.
- The UI exposes check definitions, a live status message, and a report download.

## Observed test-first sequence

1. New quality unit tests failed because `quality` did not exist. The new API test received HTTP 404 from `/api/quality`.
2. Added the audit and API. The initial nine quality tests and all five API tests passed.
3. Added malformed-input and missing-file tests. A new nontext-field regression test exposed four failures: numeric values in award key, award ID, recipient, and agency were silently accepted. Added explicit text-field validation.
4. The browser acceptance test failed because the quality panel did not exist. Added the panel and rendering, with semantic status/table markup and a keyboard-visible download link.
5. A browser regression test exposed stale audit provenance after a simulated report failure. Cleared stale provenance and hid the unavailable report link while preserving the other library views.
6. The first staged-data byte check found seven files altered by Git's automatic line-ending normalization. Added Git attributes that preserve every data file byte-for-byte and treat raw archives as binary. Restaged data and reran the byte check before committing.

## Verified behavior

- Full Python suite: 37 tests pass (24 existing plus 13 added in this checkpoint).
- `python intake.py verify`: included case data and all 16 retained raw artifacts verify; the 50-row CSV reproduces from its source response.
- JavaScript syntax check passes.
- The staged-data check verifies the actual Git blobs against all 24 local data files, preventing checkout-related evidence hash changes.
- Local Edge checks pass for replay, date gating, search, historical/modern separation, award filtering, quality status/download, failure-state cleanup, and mobile width.
- The current 50-row award sample has zero warnings and zero informational findings under these eight checks. This is not a finding about fraud, source completeness, or source accuracy.

## UX basis and limits

Used W3C guidance for [status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [visible keyboard focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [table structure](https://www.w3.org/WAI/tutorials/tables/), and [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). The download control has a 44-pixel minimum height. Validation is automated and browser-based; no screen-reader study, user research, or full WCAG conformance audit has been conducted.
