# CP-007: reproducible learning data

Acceptance tests were written first and failed on the missing fixture module. Five tests now cover deterministic regeneration, source sensitivity, fictional identities and learner-label separation, planted row traceability with a benign control, empty input, and byte-for-byte reproduction of committed artifacts.

Built 6,000 synthetic transactions from seeded sampling with replacement of the retained public award obligation magnitudes. The bounded amount transformation, fabricated dimensions/dates, source hash, every bootstrap draw, version and seed are documented in the instructor manifest. Real recipient identities are absent from learner data. Source awards are not evidence of payment activity or misconduct.

Four planted review patterns and one benign repeating-payment control have explicit explanations and transaction IDs in a separate public answer key. This is an educational separation, not access control. The data remains usable without the key. No predictive performance claim is made.

Commands: `python learning_fixture.py build`, `python learning_fixture.py verify`, and the full `scripts/run_checks.py` in the optional-dependency environment. Regeneration is offline. Source refreshes change the fixture and must be treated as a new reviewed course-data version.

Debugging: a fixture mismatch means a file or upstream snapshot differs; inspect the diff and source provenance before rebuilding. Empty or nonpositive sources are rejected. Keep CSV money as integer cents; divide by 100 only for display.

Validation: all 93 tests pass with zero skips, along with publication, raw-byte, reproducibility, and syntax checks. No R or Power BI execution is claimed by this data-only checkpoint.
