# CP-002: source freshness

Acceptance: independently report publication/update age and last successful retrieval age; preserve unknown dates; detect malformed/future metadata; use an explicit fixed clock in tests; do not let a failed refresh reset the last successful retrieval.

Test-first evidence: the initial unit run failed because the freshness module was absent; the API test failed because the response lacked freshness metadata. The browser acceptance check then failed because source clocks were not displayed.

Implemented a pure fixed-clock assessment, API metadata, separate source/award indicators, and an extracted browser quality flow. A retrieval-age threshold is explicit and defaults to 30 days. Old historical publication dates remain descriptive; a recent download does not imply legal-status verification or factual correctness.

Validation: 45 Python tests pass; browser checks pass, including independent clocks and the existing quality failure recovery. New cases include a timezone offset crossing a UTC date boundary and a failed refresh after a prior successful download.
