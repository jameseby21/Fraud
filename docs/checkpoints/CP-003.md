# CP-003: encrypted local storage core

Scope: optional authenticated-encryption storage outside Git, isolated from all web routes. Documentation covers technical design and limitations only.

Test-first sequence: 15 initial tests failed because the vault module was absent. After implementation, crypto checks passed; OS permission tests required a test process permitted to set Windows DACLs and then passed. Two additional regression tests covered noninteractive unlock and initial permission failure. The latter exposed an empty placeholder left behind; cleanup was corrected while retaining overwrite protection. An API test confirms that private paths and vault routes are unavailable.

Implemented AES-256-GCM with random salt/nonce, fixed Argon2id parameters, bounded/validated envelope parsing, external-path enforcement, current-user/LocalSystem DACLs or POSIX modes, exclusive locks, expected revisions, encrypted temporary writes, atomic replacement, and passphrase rotation. The CLI accepts no password argument and prints no private paths or payloads on failure.

Validation: 63 tests pass with the optional vault environment, including 17 vault tests; public-data verification passes. The optional dependency lock pins all three packages and official wheel hashes. A fresh `pip download --require-hashes` verifies the lock. No actual private records or user vault were created; temporary test documents contain only synthetic QA content.

Limits: public web UI remains unable to unlock the vault. This is a storage core, not an audited secure desktop, multiuser service, or anti-rollback system. See SECURITY.md for memory, administrator, backup, and endpoint-compromise limitations.
