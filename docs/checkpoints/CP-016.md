# CP-016: review scoring and round lifecycle

Review found candidate point weights in player JSON revealing the intended target, speed points awarded to empty submissions, a mistaken expense exposure (USD 8,011.10 instead of USD 701.10), repeat submissions despite the lock label, and unchecked browser-storage shapes. It also found cross-case score rankings despite different maximum scores and mutable player/mode metadata during rounds.

Three regression tests were written first and observed failing for weight leakage, unsupported speed rewards, and the expense arithmetic. Game version 1.0.1 moves weights to facilitator answers, requires a supported target for speed rewards, and corrects the exposure from the ledger's 70,110 cents. Artifacts and manifest are regenerated from the generator.

The browser now captures round identity at start, prevents overlapping loads and submissions, locks a completed round, uses monotonic elapsed time, and allows retry after a failed scoring request without stopping the timer. Valid saved scores are compared only within the selected case and mode, with points, unsupported calls, and elapsed-time tie breaking. Malformed and incompatible older entries are ignored; blocked storage leaves the result visible with an explanation. Printing is enabled after a case loads.

Browser regression coverage passed malformed storage recovery, single-record round locking, mode isolation, and failed-request retry alongside the existing perfect-score, course/library, and mobile flow. Full verification passed 147 tests with zero skips, 84 staged-data byte checks, 96 linked documents, all generators, source integrity, publication guards, notebooks, and syntax checks. Physical print fit, interactive Power BI/R acceptance, and broader learner feedback remain manual.
